# 研序 · 科研工作台

面向论文与科研项目的中文工作台，用于管理进度、证据、实验图表、版本、投稿节点和下一步计划。内置 PACSR / TKDE、IoTJ、World Model + RL、BWTAC 四个项目模板。

**在线使用：[https://lccs02.github.io/cs-research-workbench/](https://lccs02.github.io/cs-research-workbench/)**

[源码仓库](https://github.com/Lccs02/cs-research-workbench) · [部署工作流](.github/workflows/pages.yml)

网页由 GitHub Pages 托管，无需 ChatGPT 登录。科研记录在当前浏览器中解密、编辑并加密保存，仓库仅提供程序与空白模板。

## 功能概览

| 模块 | 功能 |
| --- | --- |
| 科研总览与项目详情 | 查看项目状态、任务进度、待补证据、下一步计划和风险，按论文筛选 |
| 统一时间线 | 汇总投稿、汇报及个人计划节点，区分已确认日期、个人计划和待核对日期 |
| 实验与图表 | 记录实验状态、图表说明及可核查来源 |
| 审稿追踪 | 保存审稿意见、处理方案和当前处理状态 |
| 阶段周计划 | 按周安排任务，查看待安排与逾期事项 |
| 版本档案 | 管理论文、代码、实验与检查点的版本索引，以及工作台备份 |
| 证据中心 | 区分已验证结果、待人工确认和研究设想，控制论文可用范围 |
| 进度摘要 | 生成、归档、复制或下载内部进度摘要与对外事实稿 |
| 截止提醒 | 查看未来七天与逾期事项，导出系统日历提醒 |
| 口令与备份 | 自行修改口令，重新加密本机记录，导入或导出数据备份 |

## 首次使用

### 恢复已有科研记录

1. 打开上方在线地址。
2. 点击 **选择科研备份并恢复**，选择单独收到的加密 JSON 备份。
3. 输入这份备份对应的口令，点击 **解锁工作台**。
4. 进入后核对项目、任务与摘要，再继续更新记录。

迁移备份与口令通过私人渠道单独提供，均不包含在本仓库中。若已经创建过本机记录，导入前请先导出当前备份，避免覆盖尚未备份的修改。

### 创建空白工作台

在首次打开的页面设置一个**至少 10 个字符**的新口令，点击 **创建空白工作台**。四个项目模板不包含私人科研记录，需要自行填写状态、任务和证据。

## 日常使用

- **更新进度**：进入对应项目，编辑状态、下一步计划或任务；完成任务不会自动提升证据等级。
- **整理证据**：在证据中心填写来源、核验人、核验日期及允许使用的范围。
- **准备投稿或汇报**：选择项目与用途生成摘要；可复制或下载 Markdown，也可在摘要档案中查看历史记录。
- **备份数据**：点击右上角的备份图标，或进入 **版本档案** 导出加密备份。
- **锁定空间**：点击右上角锁定图标；再次使用时输入当前本机口令解锁。

版本档案仅保存文件名称、说明和来源链接等索引，不会上传或托管所关联的论文、日志、代码与检查点文件。

## 证据与日期规则

### 哪些内容可以进入对外事实稿

| 证据状态 | 含义与使用范围 |
| --- | --- |
| 已验证结果 | 必须有来源、确认人和有效核验日期；是否论文可用仍需单独标记 |
| 待人工确认 | 保留观察与待补材料，不能作为已验证结论 |
| 研究设想 | 记录假设和计划，不能作为实验结论 |

只有**记录类型为“证据”、状态为“已验证结果”、来源与人工核验信息完整，并标记为“论文可用”**的条目，才进入对外事实稿。任务完成、材料归档、已有图表或论文录用，均不会自动满足这组条件。

摘要采用规则式提取，不调用生成式模型补写研究结论；工作台也不会替代人工复现实验或核验原始数据。

### 日期的确定性

| 日期依据 | 工作台行为 |
| --- | --- |
| 已确认 | 按记录日期用于时间线、提醒与临近节点检查 |
| 个人计划 | 明示为个人安排，不等同于官方截止日 |
| 待核对 | 作为占位信息单列，不触发自动摘要或日历导出 |

项目状态及日期依据由用户维护，工作台不连接外部投稿系统，也不会自动查询官方会议日程。

## 修改口令

1. 解锁工作台后，点击右上角 **修改口令**。
2. 输入当前口令、两遍新口令。新口令须**至少 10 个字符**，且不能与当前口令相同。
3. 保存后，本机现有记录会使用新口令重新加密。
4. 在完成提示中点击 **下载新备份**，之后使用新口令解锁本机记录或这份新备份。

修改口令只影响当前浏览器中的记录。其他设备不会自动修改口令；之前导出的旧备份仍使用导出时的旧口令。工作台没有账号或口令找回服务，请自行保管口令。

## 备份与换设备

| 文件格式 | 内容与使用方式 |
| --- | --- |
| 加密 JSON | 完整工作台备份，包含项目、各类记录、摘要和更新记录；解锁页或版本档案中均可导入，需要对应口令 |
| 明文 JSON | 完整数据导出；在已解锁工作台的版本档案中导入，仍须通过证据规则校验 |
| Markdown | 单份进度摘要，供阅读或汇报使用，不用于恢复整个工作台 |
| ICS | 任务与节点的日历文件，不用于恢复整个工作台 |

换设备时，先在原设备导出最新加密备份，再在新设备打开网页并恢复。后续编辑不会自动写回先前下载的备份。

数据绑定当前浏览器配置与网站来源；不同设备、浏览器或无痕窗口不会自动共享记录。清除网站数据可能删除本机记录，更新网页时无需清除网站数据。

## 自动摘要与截止提醒

- 网页**打开且已解锁**时，检查未来七天内尚未完成的投稿／汇报节点，按节点、按北京时间日期去重归档内部摘要。
- 待核对日期不触发自动摘要；普通任务完成也不等于实验结论已验证。
- 提醒面板汇总未来七天及尚未完成的逾期事项。
- 点击提醒面板中的 **导出日历提醒**，可导出今天及以后的未完成事项；文件声明提前一天提醒，实际通知取决于所用日历的导入与通知设置。节点调整后请重新导入。

**当前版本没有服务端定时任务，关闭网页后不会在后台生成摘要，也不会自行发送邮件或系统通知。**

原 ChatGPT 每天 8:30 的自动任务仍关联原 Sites 工作台，无法读取本版本保存在浏览器中的编辑；它不等同于 GitHub Pages 版本的自动检查。

## 数据与加密边界

- GitHub 仓库与网页程序公开，私人科研记录及其加密备份不提交到仓库。
- 使用 Web Crypto：AES-256-GCM 与 PBKDF2-SHA256，600,000 次派生迭代、随机 16 字节盐，每次加密使用随机 12 字节 IV。
- 口令不上传，解密密钥仅保留在当前页面内存中，本机持久保存的是加密数据。
- 修改口令时验证当前口令并生成新的密钥、盐和加密数据，保留原有工作台记录。
- 保存与修改口令会检查其他标签页是否更新了记录，发生冲突时提示重新解锁。

这是客户端数据加密，不是服务器账号或访问控制系统。明文导出、摘要和日历可能包含内部记录，应妥善保管；仓库管理员能够修改程序代码，使用时应信任所加载的版本。加密并不替代对科研证据真实性的人工核验。

## 本地开发

使用 Node.js 24；项目声明最低版本为 22.13。

```bash
git clone https://github.com/Lccs02/cs-research-workbench.git
cd cs-research-workbench
npm ci
npm run dev
```

按终端输出打开开发地址。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动开发服务器 |
| `npm test` | 验证证据规则、摘要、日历和加密行为 |
| `npm run build` | TypeScript 检查并生成生产文件 `dist/` |
| `npm run preview` | 预览已构建的生产文件 |

技术栈为 React、TypeScript、Vite、Zod、Lucide React 与 Web Crypto。

## 发布到 GitHub Pages

本仓库已配置 [自动部署工作流](.github/workflows/pages.yml)。后续推送到 `main` 会依次安装依赖、运行测试、构建并发布 `dist/`。

如需在自己的仓库部署：

1. 在 **Settings → Pages → Build and deployment** 中将 **Source** 设为 **GitHub Actions**。
2. 将源码推送到 `main`，或在 Actions 中手动运行 **Deploy research workbench**。
3. 等待工作流成功后，使用 Pages 设置页提供的网址访问。

应用使用相对资源路径，支持 GitHub Pages 项目子路径，不依赖原 `chatgpt.site` API、ChatGPT 登录或 Cloudflare Worker。
