# 研序 · 科研工作台

中文科研项目、证据与投稿进度管理工具，部署在 GitHub Pages。

## 使用

打开发布网页，首次选择单独收到的科研备份，并输入随备份提供的迁移口令。也可设置新口令创建空白工作台。口令不在仓库中，无法通过 GitHub 找回。

- 保留项目总览、统一时间线、实验图表、审稿意见、周计划、版本索引、风险和摘要。
- 区分已验证结果、待人工确认和研究设想。只有证据类型、人工已核验、来源/确认人/核验日期完整且标记为论文可用的条目，才进入对外事实稿。
- 编辑在浏览器中加密并保存到当前设备。页面右上角可导出加密备份、锁定；版本档案中可导入加密/明文备份。
- 解锁后点击右上角“修改口令”，验证当前口令并输入两遍新口令（至少 12 个字符）。修改在本机重新加密全部现有记录；完成后可直接下载新备份。旧备份仍使用导出时的旧口令，其他设备不会自动改密。
- 换设备需要导入最新加密备份。迁移备份是静态快照，不会自动包含之后的编辑。清除网站数据可能删除本机记录，请定期备份。
- 打开并解锁网页时检查未来七天的投稿/汇报节点，按节点、按天去重归档摘要；日期待核对的节点不会触发。
- 关闭网页后没有服务端定时检查。提醒面板可导出 `.ics`，导入系统日历后由日历提供提醒；节点修改后需重新导入。原 ChatGPT 自动任务关联的仍是原 Sites 记录，无法读取本机编辑。

## 数据边界

GitHub 仓库和网页壳公开，仓库不包含私人科研记录或其加密备份；迁移文件通过私人文件单独提供。本机存储只写入加密数据，解密密钥仅保留在当前页面内存中。采用 Web Crypto AES-256-GCM 与 PBKDF2-SHA256（600,000 次，随机 16 字节盐，每次保存随机 12 字节 IV）。口令不会上传，没有前端硬编码密码或验证后显示明文数据的伪保护。

这属于客户端数据加密，不是服务器账号系统。不要将口令提交到仓库；导出的明文 JSON、Markdown、日历文件包含内部内容，应自行妥善保管。仓库管理员能修改应用代码，发布代码应来自可信提交。

## 开发与发布

Node.js 24（至少 22.13）：

```bash
npm ci
npm test
npm run dev
npm run build
```

首次在仓库 Settings → Pages → Build and deployment 中将 Source 设为 **GitHub Actions**。之后推送 `main` 会通过 `.github/workflows/pages.yml` 测试、构建并部署 `dist/`。也可在 Actions 中手动运行部署。

应用使用相对资源路径，支持 GitHub Pages 项目子路径，不依赖原 `chatgpt.site` API、ChatGPT 登录或 Cloudflare Worker。

## 验证

`npm test` 检查证据门槛、非法日期、对外摘要筛选、自动摘要去重、待核对日期过滤、日历行折叠、加密往返、错误口令、篡改检测与随机 IV。`npm run build` 执行 TypeScript 检查及生产构建。
